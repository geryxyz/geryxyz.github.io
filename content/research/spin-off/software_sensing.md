Software sensing extends [[research/software_visualization_and_comprehension|software visualization]] beyond sight, using other senses to communicate properties of source code and software systems. Instead of relying only on diagrams or visual metaphors, developers could **hear or feel** characteristics of the code they are exploring.

For example, different chimes could signal when a developer enters code associated with bugs or potential defects. Ambient sounds could communicate software metrics without requiring constant attention to a chart or dashboard. Haptic devices, such as vibration gloves, could let a developer *feel* properties of code elements while navigating a software representation.

These examples suggest a broader direction for exploring **multisensory software comprehension**: mapping software structure, quality, and behavior onto sound and tactile feedback. The goal is to make otherwise abstract software properties more immediate and intuitive, and to investigate which sensory mappings genuinely help developers understand a system.
