My research focuses on understanding how software is built, tested, maintained, and improved—and how tools can better support the people doing that work. I combine static and dynamic software analysis with measurements of development activity, visualization, and feedback from developers. A recurring goal is to turn technical data into insights that are useful in practice.

## Research areas

- [[research/human_centered_software_engineering|Human-Centered Software Engineering]] — Developer behavior, productivity, interaction, knowledge, and feedback. How can we better understand software development work and use human expertise to improve automated tools?
- [[research/software_analysis_and_quality_assurance|Software Analysis and Quality Assurance]] — Static and dynamic analysis, testing, coverage, test-to-code traceability, and fault localization. How can we find faults and assess software and test quality more effectively?
- [[research/software_visualization_and_comprehension|Software Visualization and Comprehension]] — Interactive representations of software systems, software cities, and integration with development environments. How can complex code become easier to explore and understand?
- [[research/software_security_and_ai_assisted_engineering|Software Security and AI-Assisted Engineering]] — Vulnerability management, actionable analysis results, and security challenges in AI-assisted development.
- [[research/data_driven_software_engineering|Data-Driven Software Engineering]] — Software metrics, development-effort prediction, machine learning, and expert-guided analysis. How can data help people make better engineering decisions?

These areas are interconnected: for example, code coverage can support test-quality assessment, fault localization, and visualization, while developer feedback can make analysis results more actionable.
